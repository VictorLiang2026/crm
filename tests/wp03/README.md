# WP03 验收复跑

本目录只验证 WP03。先读取根 AGENTS、环境/安全边界及 `specs/target-crm-v1` 三个规格文件。

## 不落库夹具

`npm run test:wp03`：确认、身份冲突、拒绝非法种子参数、错误映射、审计关联与隔离 UI。

`npm run test:wp02` 和 `npm test`：样本参与普通计算/提示，以及相邻旧功能。浏览器临时目录需要可写且有足够空间。沙箱无法创建测试配置时，按本机授权运行；不得删改断言来转绿。

## 已存在场景的真实只读验收

1. 由授权的 CloudBase PG 只读工具执行 `tests/wp03/verify-readonly.sql`，保存聚合结果至 `tests/security/.results/wp03-readonly-database.json`。仅输出数量/布尔检查，不导出完整 ID 清单。
2. 保持 `node tests/wp03/live.cjs` 创建的窗口打开，由用户使用 prtest 登录。已有窗口可复用，无需再次生成样本。
3. 运行 `node tests/wp03/readonly-live.cjs`。它读取 helper 记录的本机调试端口，只使用该真实页面的登录态，依次检查 50 个 public 表/视图 HEAD 拒绝、状态、5 类无效种子请求、数量不变与 Today 普通取数；然后打开专用页签检查场景、人物、旧客户/活动详情、漏斗及 390px 场景布局。
4. 最新报告为 `tests/security/.results/wp03-readonly-live.json`，每次另存带时间戳的历史报告。PASS/FAIL/MANUAL_LOGIN 分开记录；不保存令牌、密码、真实客户文本或完整 ID 清单。退出码 0 仅代表本次只读检查通过，1 代表失败，2 代表需登录；不表示 WP03 整体验收通过。

真实探针不提交登录信息，不调用有效的 dryRun/confirm/execute，不运行 AI 生成，不点击业务保存。非法种子请求包含无法匹配的预览 ID 或明确非法字段；它们必须在写业务前被拒绝。出现意外失败后停止后续探针。先检查页面的登录状态和五分钟活动时限；即使 JWT 仍有效，页面已锁定也必须由用户本人再次登录，不修改活动时间戳或绕过登录页。

SQL 检查针对 WP03 当前固定场景：10 初始行及已产生的 Action/Command 和 task/run/result。后续 WP 新增其他种类的衍生行时，应在对应 WP 中扩展实际存在性检查，不把未知种类默认为通过。

## Today 真实验收与证据边界

运行 `node tests/wp03/today-live.cjs`：复用用户本人登录的窗口，经普通 Today 页面生成一次今日建议；有缓存时点击既有重新生成按钮，不删除缓存、不修改登录时限、不写业务记录。记录新结果耗时、规则/AI 来源、样本纳入及可见提示；只保存布尔值、数量和源码哈希。退出码 0/1/2 分别代表通过/失败/需人工登录。该操作会实际调用已配置的 AI，需在 WP 授权范围内运行。

历史两次 60 秒失败保存在 `wp03-ui-today.json` 和执行报告；修复后真实结果另存 `wp03-today-live.json` 及带时间戳副本，不覆盖历史失败。源码哈希必须与被验收产物匹配，时间必须晚于部署；不能用 candidates、cockpit、模拟 AI 或源码一致替代真实生成。只读探针的整体状态为 NOT_ASSESSED，表示它不判定整个 WP03；正式收尾须同时检查 Today 实页、数据库、真实登录、回归和发布结果。

390px 是桌面浏览器视口模拟，不是手机真机验收。真实 AI Search 与首次生成/幂等重放沿用 WP03 报告中的单独证据；本工具不会重跑这些写入。

场景存在后禁止运行 `database-rollback.sql`：该事务夹具只适用于初始台账为空的阶段，会主动拒绝已有样本；不能为了重跑清空台账或业务数据。

这些测试文件不上传静态托管。业务失败未解除前保持发布阻断；修复发布前测试与修复后真实验收分开保留，不以工具检查成功宣称 WP03 完成。
