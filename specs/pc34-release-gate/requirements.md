# PC34 权限、业务回归与双语 iPad 发布门禁

## 范围

承接 PC33 后的 PC34-A 字典修复发布 `3f522b88000aa5018c9d0fd2ef9fc58a068f5d72`。本包只扩充 `tests/wp01`、`tests/security`、隔离业务与界面测试及说明，不修改业务页面、云函数、`public` 数据对象或权限。只读取 `public`；不访问其他 schema 或带禁止前缀的云函数。测试沿用虚构样本及现有回滚事务。

## 验收条件

1. 当发布门禁读取新鲜的 `public` 目录时，应逐项验证 anon、authenticated、service_role 对关键业务表、AI 敏感审计表及命令 RPC 的允许与拒绝范围；匿名网关和服务角色实际只读调用应有独立结果。真实登录缺席时应显示人工待验，不能记为通过。
2. 当命令输入出现换人、跨 Person、越权字段、旧版本、过期确认、重复消费或并发冲突时，相应隔离回归应拒绝或返回原回执，任何失败应阻断发布。
3. 当 Person、互动、事实、关系、机会、Action、Outcome、反馈任一必要链路的已登记隔离回归失败，或旧路由失败时，发布门禁应阻断。实际登录与人工业务确认仍单列，不用模拟结果冒充线上写入成功。
4. 当新增 Console 模块引用缺失的中英字典键、枚举无对应显示，或关键错误、空态、无障碍名称与提示不全时，静态及隔离浏览器检查应失败。iPad 820×1180 和 1180×820 的表格、弹层、触控与键盘可用性应有证据；不新增手机验收。
5. 当权限漂移、报告缺失或过期、测试后源码变化、关键测试失败时，门禁应阻断；原有一小时有效期和源码指纹判定保持不变。

## 边界与人工项

不新增生产测试种子，不用真实客户做破坏性验证。真实登录、云函数和人工确认能实际执行的逐项记录；缺凭据或未执行项标明 `MANUAL_LOGIN` / `UNVERIFIED`。发现产品缺陷只记录证据，另立修复包。
