# PC34 设计

## 门禁结构

在 WP01 保留原始目录、匿名探针、登录、回归、报告有效期和指纹。新增一个关键检查 `pc34-business-security`，运行只读服务角色权限探针、关键命令与跨模块隔离测试、双语 iPad 检查。失败为 `FAIL` 并进入现有阻断逻辑；没有服务凭证时为 `UNVERIFIED`，同样阻断发布。报告不保存账号、令牌、人物内容或模型文本。

目录快照继续与已审阅的 `expected-public-baseline.json` 精确比较；PC34 对敏感关系与 RPC 另加显式矩阵断言。匿名实际拒绝沿用 `gateway-probe.cjs`；真实 authenticated JWT 仍使用独立登录窗口，结束即退出。服务角色通过 CLI 的单条 `public` 只读 SQL 实测权限，不查询业务正文。

跨模块测试复用 PC04–PC33 已落地的隔离测试，补充聚合清单，保证关键链路和相邻旧路由一起进入发布前运行。新前端检查读取统一 `i18n.js`，检查静态键及枚举映射，并在隔离浏览器用两种语言和 iPad 横竖屏验证主要页面、错误及空态、触控与键盘。缺失的人工线上执行项在报告中保持可见。

## 发布和恢复

只发布测试、工具与文档的 Git 提交和标签；云端业务产物不变。沿用 `release.ps1` 的发布前后全量源码核对。恢复时基于 PC34 标签前一发布提交做恢复提交，不强推；数据库无需迁移或回滚。
