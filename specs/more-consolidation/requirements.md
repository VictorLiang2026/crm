# 更多功能精简整合：已批准需求

日期：2026-10-24。用户已批准 M00–M19 顺序执行及常规自动审核；每包验证、发布完成后自动进入下一包。

## 目标

个人保险营销使用，以 Person 为中心支撑客户经营、招募发展、活动与日常跟进。减少重复入口和跨页跳转；复用现有能力，保留尚未等价覆盖的旧功能。不因精简导航删除业务对象。

## 验收要求

- R1 当用户从人物、活动或报表深链进入时，系统应保留对象、页签、日期及浏览器前进后退语义。
- R2 当已有 Console 能力与旧入口重叠时，系统应优先呈现对应业务工作区；旧 URL 继续可访问，缺口有明确兼容入口。
- R3 当导入文件时，系统应区分保存原件、解析草稿、确认应用；失败可重试且不重复创建记录，不自动产生事实、行动、机会。
- R4 当修改旧客户机会时，系统应校验身份、关联、版本、允许字段与状态，以原机会 ID 保存；不扩大自然语言命令范围。
- R5 当查看 AI 历史时，系统应支持有边界的筛选和分页，区分旧建议与新结果，区分反馈、执行、实际结果及已审核学习。
- R6 当查看知识与分析时，系统应显示来源、状态、统计时间窗和覆盖范围；缺失证据不包装成完整结论。
- R7 当使用回收站时，系统应沿用现有各对象删除与同批恢复语义，保留未覆盖的批量恢复。
- R8 当使用任何本轮新界面时，系统应提供默认简中和英文，iPad 横竖屏可用；不破坏既有手机入口。
- R9 当完成工作包时，应记录影响、回归、发布提交、标签、云端范围和未验证项；失败不得标记完成。

## 安全边界

仅 public；不访问 pr 或 pr_*。不删除或重命名已有表、视图、云函数及路由。数据库变更提供 migration/rollback，检查视图依赖。保留 callFn、鉴权、RLS、旧页面兼容及 AI Gateway 配置。关键 AI 写入保留 Command → Plan → 服务端 Preview → 人工 Confirm → 范围 Execute。人物候选仍服务端解析并由人确认。
