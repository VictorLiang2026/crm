# 执行规则与授权

1. 用户于 2026-10-24 批准原 M00–M19 方案，逐包自动审核、验证与发布，完成后自动进入下一包。不重复请求已经批准的常规实现选择。
2. 自动开发审核不等于代替业务确认。关键业务操作仍保留应用中人工确认；未接执行器拒绝写入。没有具体授权的真实数据写入不作测试。
3. 新风险或原计划外行为变化先说明影响与所需授权；登录必须人工且无有效会话时才请求用户操作。门槛失败先诊断，不绕过。
4. 每包开始确认 Git/云端基线、前包完成状态、影响面；每包只完成指定范围。额外发现登记，不顺手重构。
5. public-only；不访问 pr/pr_*，不删除或重命名既有业务对象/路由。新 schema 变更成对 migration/rollback，并核查依赖视图及权限。
6. Console 新界面采用既有模块、双语 t()、iPad 尺寸。旧 admin.html 保持单文件、callFn、鉴权、软删恢复及手机兼容。
7. AI 模型由 Gateway/CloudBase 选择；人物身份解析由服务端 PersonService.resolveName()，由人确认；不自动采纳模型推断。
8. 跨模块必做 regression。记录实际命令、结果、测试数据范围和未验证项；不把源码哈希、页面加载或隔离测试冒充生产完整验收。
9. 每包测试后仅部署变更资源；提交、推送、标签与三端核对按 tools/release.ps1。报告失败就停该发布，修复后重跑，不跳到下一包。
10. 不提交其他会话变更、密钥或测试客户内容。原工作区未提交 PC36 文档独立保留；执行副本只提交本包文件。
11. 每包状态：待执行 → 执行中 → 验证中 → 已发布，或阻塞（具体原因）。已存在且核验等价的功能记“复用已覆盖”，不重复建设。
12. M19 不实际清退任何对象。任何后续删除须逐项独立授权，遵守 PMC 观察期及历史兼容要求。
