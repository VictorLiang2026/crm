# iPad 横屏体验优化需求

## 问题与目标

CRM 当前由新版 Console 与保留的 `admin.html` Legacy 页面共同提供业务入口。iPad Pro 12.9 英寸第 5 代横屏空间适合并列查看业务列表、详情和上下文，但不同页面的导航、表格、详情分区和编辑弹层使用了多套样式规则。本工作包统一横屏展示与触控交互，同时保持现有业务行为和兼容入口。

目标视口为全屏横屏约 1366×1024 CSS 像素。Safari 浏览器栏可能减少可用高度，应使用动态可视高度和安全区域约束弹层、固定工具栏与滚动内容。

## 用户故事

- 作为 iPad 横屏用户，我希望能持续看到主要导航、当前页面和快捷记录入口，以减少迷路与不必要的页面切换。
- 作为客户经营人员，我希望在人物、机会、活动和招募工作区并列查看相关列表与详情，以减少往返跳转。
- 作为数据表用户，我希望横屏下重要字段、筛选、排序和分页关系清楚，并可在需要时查看完整字段。
- 作为 iPad 触控用户，我希望常用操作有足够大的点击区域，长表单和详情弹层适合横屏阅读与输入。
- 作为中英文用户，我希望横屏布局均能容纳两种语言，不截断主要入口与关键操作。

## 范围

- Console：导航外壳、今日/行动中心、人物目录和详情、机会、活动和活动详情、招募和目标、AI、知识管理、分析和日报、回收站、设置、导入及维护页面。
- Legacy：客户工作台、客户列表/详情、候选人工作台/详情、活动列表/详情和仍保留的旧入口；只修改 iPad 横屏样式或交互表现，不抽离 `admin.html` 的既有业务实现。
- 共用表格、页面头部、表单弹层、操作按钮、加载/错误/空状态和导航返回行为。

## 非目标

- 不设计或验收 iPad 竖屏及手机界面；窄窗口仅保持无崩坏，不列入专门优化目标。
- 不新增或更改数据库对象、云函数、业务 API、登录、权限、数据语义或 AI 业务能力。
- 不删除或重命名页面、路由、云函数、表或视图。
- 不统一重构 Legacy 架构，不扩大到未列出的桌面重设计。

## 约束与兼容要求

- Console 数据继续通过现有 `data.js` / `callFn`；保持登录/RLS、写入预览与确认流程、软删除和恢复语义。
- 保持现有路由、旧书签跳转、筛选/排序/分页和人物详情深链接有效。
- `admin.html` 仍为旧业务实现的单文件；只在获准范围修改横屏表现。
- 所有新增或变更 UI 文案同时提供简体中文与英文，集中在 `crm/js/modules/console/i18n.js` 并通过 `t(key)` 获取。
- 采用现有品牌色、字体栈、图标和原生模块结构，不升级运行时或引入新框架。

## 验收标准（EARS）

1. 当用户在目标 iPad 全屏横屏打开 Console 时，系统应显示完整主导航、页面标题和快捷记录入口，且中英文下均无重叠、裁切或不可见的主要入口。
2. 当用户在人物、机会、活动或招募页面选择一个记录时，系统应在横屏工作区展示所需详情或上下文，并保留现有路由语义、业务内容和返回到原列表状态的能力。
3. 当用户查看横屏表格时，系统应保持既有业务字段与排序/分页行为，并使主要对象和当前阅读位置易于辨认；辅助字段仍可访问。
4. 当用户在 iPad 横屏打开表单或详情弹层时，系统应依据可视视口适配大小、滚动和安全区域，不遮住必须完成的输入与主要操作。
5. 当用户使用触控、键盘或指针操作时，系统应保留可见焦点/选中/按下状态；常用触控操作目标以 44×44 pt 为设计目标，并避免相邻危险操作过密。
6. 当用户使用旧 URL 或 Legacy 入口时，系统应保持既有目标、数据和兼容行为；本轮样式优化不得改变登录、写入、删除、恢复和接口结果。
7. 当页面展示新或修改后的文字时，系统应通过统一 i18n 字典提供简体中文与英文，默认简体中文。
8. 当工作包完成时，发布记录应包含目标视口回归结果、涉及页面与资源、Git 提交/标签、云端部署资源和未验证项。
