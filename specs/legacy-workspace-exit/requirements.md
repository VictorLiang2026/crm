# 需求：旧版入口退出与新版能力补齐

2026-10-25。完整产品分析：[升级方案](../../docs/work-packages/legacy-workspace-upgrade-20261025.md)。

## 授权范围

用户明确选择“实施这11项清理，其余先出方案”。仅L00可执行；L01–L08为供审核的后续工作包，不因上一轮M00–M19自动执行授权而继续开发。

## 验收要求

- R1：打开More时，系统只在兼容区展示customers、funnels、ai-suggestions、more/photos、speakers、recruit/goals六项；其余11项卡片不存在。四主入口、工作区捷径、快速记录、退出保留。
- R2：访问既有17个admin.html URL时，系统仍显示对应页面；不得删除/重命名路由、数据对象或后台服务。
- R3：用户从新版设置进入高级维护时，仍能找到受控测试工具；从统一回收站进入批量恢复时，仍能找到原两类入口。不能把移出菜单等同于全部原生替代。
- R4：在iPad横竖屏中英双语使用More时，卡片、折叠、标签与路径均正确；默认中文，全部新文案经t()；不主动改变既有手机布局。
- R5：形成逐项覆盖矩阵和六项产品升级建议，明确有价值的缺口、归属、复用接口、取消/不迁移内容及退出条件；不得用名称相同推定等价。
- R6：后续迁移涉及重要AI写入时，必须复用服务端身份核实及Preview/Confirm/Execute链；仅只读建议不能触发关键业务影响，模型通过已有配置选取。
- R7：代码变化完成后执行相邻功能回归、WP01、精确静态发布、Git提交标签与三端核验；明确生产业务与实机未验证项。

## 非目标

本轮不实现剩余六项，不新增数据库对象/云函数，不改数据/权限/登录/恢复逻辑，不改admin.html，不删除旧地址，不导入公司政策、不添加星座、不扩建团队管理。
