# 每日行业激励语（扩展）

## 用户故事

- 作为 CRM 使用者，我希望按展示时段、推荐值下限和轮播策略筛选激励语，让前台只展示符合当前设置的内容。
- 作为语录库维护者，我希望编辑每条记录的推荐值，批量导入 JSON、Excel、CSV 或 TSV，并在导入前审阅相似内容。
- 作为维护者，我希望完全相同的语录自动排除；可能相似的语录单独列出，由我决定保留已有或导入新版；没有相似项的行默认选中导入。

## 验收条件（EARS）

1. 当管理者保存设置时，系统应保存推荐值下限（0–10，含边界）及“轮播完成前允许重复”选项，并按用户范围隔离。
2. 当首页选择或更换语录时，系统应仅从已启用、推荐值非空且大于等于下限的语录中选择，并服务端复核已保存槽位和候选资格。
3. 当禁止提前重复时，系统应优先且在轮播周期内只选尚未展示的合格语录；全部合格语录用完后开启新周期。当允许重复时，系统优先未展示语录，必要时才可重复。
4. 当导入 JSON、XLSX、CSV 或 TSV 时，系统应映射双语内容、主题、来源、链接、编辑改写标记和可选推荐值；缺少推荐值时按现有自动评分补齐。
5. 当导入行与已有记录完全相同，系统应自动标为跳过；当内容达到近似重复阈值，系统应单独呈现对照并要求逐项选择“保留已有”或“仍导入”；其他行默认选中。
6. 当用户确认导入时，服务端应重新核实重复情况、白名单字段与分值后再保存，并报告新增、跳过和补分数量；失败时允许安全重试。
7. 当管理者打开语录管理页时，iPad 页面应在同一行并排展示“展示时间”与“批量导入”两栏，语录编辑列表位于其下；所有新增界面文字应由 `t(key)` 提供简体中文和英文版本。
8. 当导入包或数据库迁移回滚时，系统应保留既有兼容行为；数据迁移提供只作用于 `public` 的 migration 与 rollback。

## 边界

- 展示时段仍以账号时区及本地日期稳定缓存；已确认的现有槽位只有在不再符合分值门槛或停用后才需重新选取。
- AI 只在服务端 AI Gateway 内参与受限候选选择；不绑定模型厂商；不在浏览器生成内容，也不读取客户业务数据。
- 当前范围是 iPad 管理界面；不改变登录、权限、客户流程、More 路由和 `admin.html` 旧实现。
- 不访问或修改 `pr` schema、`pr_*` 数据库对象或云函数。
