# Person Actions V1

`public.actions` is an additive Person-level action ledger. It does not replace the legacy `next_action` columns or the existing action-center view. A row belongs to one active Person and may refer to an opportunity, interaction or activity. The database checks that an interaction belongs to the same Person and that an opportunity belongs to the Person's linked legacy customer; activities have a normal foreign key. Soft-deleted source records are rejected by `ActionService.createManual()` before writing.

Priority is `low`, `medium`, `high` or `urgent`; status is `open`, `in_progress`, `completed` or `cancelled`. All five optional scores are on a 0–100 scale; `priority_score` is stored, not recalculated from the other scores. Completion requires a timestamp and actor UID. An AI-prefixed source additionally requires confirmation actor and time in the database. The first service writer is manual only: it fixes `source='manual'` and never accepts an AI candidate as a persisted action. The service exposes `listForPerson`, `createManual` and `complete` through an authorized server-side database request callback. It is not wired to a Cloud Function or page in this work package.

The new table has forced RLS. Only `service_role` receives SELECT, INSERT and UPDATE; `anon` and `authenticated` receive no table or sequence privileges. CloudBase initially applied a broader default service-role grant, so `cloudbase/migrations/20260928025525_actions_privileges.sql` explicitly revokes it before granting only these operations. The first forward migration is `cloudbase/migrations/20260928023429_actions.sql`; its paired rollback refuses to drop a table containing rows or with dependencies. The privilege migration has a separate, manually reviewed rollback because reversing it would restore DELETE and TRUNCATE.
