# Person Context Items V1

`public.context_items` stores a bounded, typed unit of Person context. `item_type` is exactly `fact`, `signal`, or `inference`; changing the type or provenance of an existing row is rejected. A Fact is an asserted claim, a Signal is an observed indicator, and an Inference is an interpretation. The `confirmed` flag is reserved for human review of the row **within its existing type**; it never converts a Signal or Inference into a Fact.

Each row belongs to `public.persons` and may point to a `public.interactions` row for the same Person. The table stores `category`, text `content`, optional `structured_value` JSONB, `source_type`/`source_id`, a 0–1 `confidence`, optional validity bounds and last verification time, and creation time. `source_type='manual'` has no source ID; other sources require one. The SQL guard checks that an interaction reference belongs to the same Person. Source IDs are provenance references, not foreign keys to arbitrary source tables.

`confirmed` defaults to false. A confirmed item requires `confirmed_by_uid` and `confirmed_at`. For AI provenance, `source_type` must be `ai` or begin `ai_` (for example `ai_results`); an AI-sourced Fact cannot be inserted directly as confirmed. It remains a Fact Candidate (`item_type='fact', confirmed=false`) until a later, separately approved human-review workflow is built. No writer or confirmation API is introduced in V1, and the service role has no direct update privilege. The database cannot detect a future writer that lies about `source_type` or a forged UID, so that write boundary must verify real caller identity and provenance before it is granted access.

The table uses forced RLS and grants only `SELECT`/`INSERT` to `service_role`; `anon` and `authenticated` have no table access, and `service_role` has no direct `UPDATE`/`DELETE` grant. This deliberately leaves promotion/editing unavailable in V1. The migration changes no existing table, view, Cloud Function, route, or legacy behavior. Its paired rollback refuses to drop a nonempty table and uses `RESTRICT` so future dependencies cannot be removed implicitly.
