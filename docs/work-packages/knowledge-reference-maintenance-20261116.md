## 实现

1. 元数据 enabled 缺省视为 true；false 通过现有 knowledge-content 投影在服务端退出新业务调用。保留 Person 读取器原有 review_at 兼容逻辑，不将其覆盖为共享版本。会前准备、跟进策略的数据库候选过滤也排除停用及 communication_reference 内容，避免新内容占用候选上限。
2. 新增一张 service_role-only、强制RLS的 public.knowledge_record_history。触发器记录新增、编辑和启停；旧记录首次修改时补录前态。历史不授予浏览器或匿名角色，服务角色无更新/删除权限。
3. public.crm_knowledge_maintain_v1 提供维护读取、人工保存、启停、历史和内容恢复。更新及恢复校验更新时间；恢复不改变启停、审核、删除、来源归属或主资料身份。关联原件的条目按来源指纹阻止恢复到已经变化的来源上。
4. 手册内容存于既有 playbooks，标记 usage=communication_reference。使用完整正文保存回应、追问和边界，不增加复杂的业务字段。预览及导入通过现有 assistant 登录入口，预览凭证绑定操作人、完整种子哈希和十分钟有效期。只有点击确认后导入；重试跳过已有记录，包括已删除的条目，不能覆盖人工修订或复活删除项。导入若中断，可重新预览后续传。
5. 新入口 #/knowledge/communication，六列表格、全文搜索、类型及启停筛选、20条分页、独立编辑和历史对话框。原知识表增加启停和历史入口，默认显示启用记录；原路由及旧编辑保留。
6. 跟进建议的话术列表提供独立的沟通润色入口。communication_wording 通过现有Gateway选模型，读取已保存策略后生成另一个待人核对的草稿；不改原建议、不发送消息。生成后重新校验策略版本、引用时间戳、启停状态及测试数据来源。没有相关条目时返回no_match，不硬取无关参考。
7. 分卷总览排除停用子条目；覆盖基础变化会令原总摘要不再有效。审核状态与启用状态分开，启用不能将草稿变为已审核。

## 回滚

配对脚本为20261117010000_knowledge_reference_maintenance.rollback.sql。新历史、启停数据或沟通参考已经存在时，脚本拒绝移除，要求先导出并单独评估。不静默删除历史或撤销人工内容修改。

已有停用记录时，也不能直接回退到不识别enabled的旧读取器，否则会重新使用已停用内容。应保留启停过滤兼容补丁或先暂停对应读取入口，再评估版本恢复。所有回滚均不操作客户业务数据。
