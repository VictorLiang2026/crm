## 故障与修复

- 原 CLI exit 3 是 Windows JSON 参数传递问题。使用 `fn invoke ... -d @文件 --json` 后调用成功；管理调用不携带应用登录身份，`UNAUTHORIZED` 是正确拒绝，不能据此认定服务不可用。用户在独立验证窗口真实登录后，新旧招募调用均成功。
- Person 活动页原来请求 `pageSize=50`，服务端只接受最多 20，导致真实请求失败。改为每页 20 条，按需继续加载；失败保留已显示结果并重试同一页；读取至 400 条仍有后续时显示明确双语上限。空态只描述已加载范围，仍按时间线活动口径展示，不宣称完整活动名册。
- 机会目录入口原来把路由信封交给严格的查询字段校验，正常路由请求被拒绝。第一次仅移除 `action` 后真实调用仍失败，CLS 显示在 1ms 内拒绝，数据库函数独立只读调用成功。最终入口只提取 `page/pageSize/kind/status/type/personId/query` 七个业务字段，服务继续严格校验字段值；调用信封及伪造身份不参与查询，操作者仍由服务端登录身份绑定。日志未记录信封内容，不能断言具体是哪一个平台附加键。
- 上述两条读路径影响及回归范围已获得本轮用户具体批准。旧 admin、写入流程、软删除/恢复、共享认证和旧 API 保持兼容。
