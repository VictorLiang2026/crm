# WP 13.1 · 客户服务端分页

## 范围与基线

- 基线：`d7819acdd65a205dc7eae332e2a6fe167399aacf` / `release-20261001-131949`。
- 线上 `public.customers` 有 777 条未删除记录；旧 `customers.list` 一次读取全部客户和全部未删除跟进，在函数内筛选、排序，再截取最多 1000 条给浏览器。旧 `#/customers` 再在浏览器按 50 条分页。
- 首页已不依赖该客户缓存；增员新增时仍用缓存查客户。本包覆盖 `customers.list`、`#/customers` 和增员新增时的客户选择。不改 Today、活动、招募列表、回收站、SDK 或运行时。

## 实现

- `public.crm_customers_page_v1` 只读 `SECURITY INVOKER` RPC：限定排序字段，在数据库内按姓名/电话/职业过滤、按最新未删除跟进和工作台状态排序，再返回当前页、准确总数。单次最多 1000 条，页面实际请求 50 条。保留旧列表字段供 Quick Capture 人工同名合并使用。
- 保留 `customers.list` 的 `{rows,total,page,pageSize}` 响应。新增可选 `exactName` 供增员关联客户精确查找。默认排序仍按编号倒序；同值按编号升序稳定排序。
- `#/customers` 将关键词、排序、页码交给服务端。增员新增时先精确查找，再取最多 8 条相似候选，保留人工选择。
- migration：`cloudbase/migrations/20261001100000_customers_server_pagination.sql`；rollback：同名 `cloudbase/rollbacks/` 文件。未修改基表、视图、现有 RLS policy。函数只授予已能读取基表的 `anon` 与 `service_role` 执行；`authenticated` 无执行权限。

## 验证与发布

- 完整离线隔离回归：90 项通过、0 项失败、5 项预设跳过；包含登录、客户详情、跟进、活动、增员、Today 和回收站。浏览器测试工具曾因页面跳转竞态间歇超时，已改为等待目标网址和测试页面同时就绪，随后完整回归通过。
- migration 预检可执行并已应用。线上只读 SQL 验证：777 条有效客户；前两页各 50 条、无重复；精确姓名查找正确；百分号按字面量搜索；函数 `SECURITY INVOKER`，`anon` 可执行、`authenticated` 不可执行。
- 云函数 `customers` 已部署。管理端/CLI 直接调用返回 `Cam authentication failed`，因此使用独立的真实登录只读浏览器探针验证；七项分页/排序/空搜索检查全部通过，探针不回传客户内容。
- 页面 `admin.html` 已单文件上传，线上 HTTP 200 且 SHA-256 与本地相同。云端函数源码一致性、发布提交、标签及最终一致性核对见发布完成后的检查输出。

## 回滚与剩余风险

- 先恢复旧 `customers` 云函数和 `admin.html` 代码，再执行 rollback 删除新 RPC；不可在旧函数仍调用 RPC 时先删除它。
- 本包不增加索引；数据库可能仍需排序和扫描，具体索引留待 WP 13.2 根据查询计划处理。
- `recruit_candidates.list` 等其他列表的全量查询不在本包范围内，仍需后续独立评估。
