# PC34-A Console 六个缺失文案键

PC34 双语门禁审计发现现有 Console 六个 `t(key)` 引用没有字典项，页面会显示 `person`、`btn_refresh` 等原始键名。用户已明确批准先单独补齐这六项中英译文并发布，再继续 PC34。

本包仅改 `crm/js/modules/console/i18n.js`，补 `person`、`opportunities`、`work_item`、`act_legacy_status`、`btn_refresh`、`confidence_low`。影响人物/行动、机会、活动报告与状态、关系建议的显示文字。沿用原 `t(key)`、登录、接口、字段、权限、业务数据和旧页面行为；没有数据库迁移。回退只需基于 PC33 标签恢复该静态模块并创建恢复提交。

验证：六项在简体中文和英文均经共享 `t(key)` 实际返回检查；相关 Console 页面及相邻旧客户、活动、招募、回收站走现有隔离回归与 WP01 发布门禁。人物目录旧隔离测试原先把夹具挂到仍在刷新的 More 容器，产生随机超时；只将该测试的挂载点改为独立 DOM 容器，四项复跑通过。WP01 连续运行多组浏览器测试时，旧路由回归曾被统一 180 秒进程限制截断；仅把该项进程限制调至 360 秒，其他测试仍为 180 秒。旧路由在冷加载时曾达到 25 秒导航上限，诊断时页面与夹具已经加载，因此将后台隔离浏览器的导航等待上限设为 45 秒；新增参与者的服务端身份解析夹具等待上限设为 15 秒。匿名权限网关曾瞬时断线，已给只读探测加最多三次连接尝试；HTTP 权限响应仍只执行原判定。以上均只调整测试代码，不改产品行为或页面断言。发布时仅上传 `/crm/js/modules/console/i18n.js`，随后核对 GitHub、本地与在线资源；线上人工业务操作单列为未验证。

发布前结果（2026-10-18）：六键中英测试 1/1、旧路由隔离回归 108/108、匿名权限探测 70/70，WP01 为 `PASS_WITH_LIMITATIONS` 且无阻断项。真实登录、服务角色写探针、线上业务写入及手机视觉检查未由通用门禁执行；本包未写业务数据。静态托管只上传一份 `i18n.js`，线上下载与本地 SHA-256 相同。

GitHub HTTPS 偶发 TLS 握手中断，因此发布脚本仅对 `ls-remote`、`fetch`、`push` 增加最多五次短间隔重试；原有失败即停止、原子推送和事后云端核对保持不变。运行时临时使用 Git OpenSSL TLS 后端，未关闭证书校验或更改仓库远端。
