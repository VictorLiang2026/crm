# CRM 系统功能优化方案与 Codex 执行任务

日期：2026-11-06
依据：[自动化深测报告](./automated-deep-test-20261106.md)
目标：提高自动化验证可信度，基于数据改善可证明的性能热点，补齐 Person AI Gateway 覆盖，并减少重复入口维护成本。

## 1. 结论与执行原则

最新完整自动化轮次为 676 项：675 通过、0 失败、1 项 PMC11 TODO。首次轮次的 10 项失败在隔离重跑和后续全量重跑中均通过，主要表现为浏览器/CDP资源波动。现有证据没有证明生产页面或服务存在性能退化，因此先测量再优化，避免凭猜测改写业务流程。

当前已确认的方向：

1. 优先改善浏览器测试分组、失败诊断和结果归档，降低假失败及重复排查耗时。
2. 为核心列表与详情流程建立本地可重复的性能基线；只有测出稳定热点后才改对应路径。
3. 先把 PMC11 旧 AI 入口与当前 AI Gateway 的调用面、数据写入和兼容要求梳理清楚，再逐条补足新流程覆盖。
4. 保持已确认的领域边界：人物基础资料以 `public.persons` 为准；客户业务资料留在 `public.customers`；礼品以 Person ID 归属，客户附件沿用 Customer ID 与 Person 的关联读取。
5. `admin.html`、旧路由与 M07 兼容入口先保留。先统计消费者、确认新入口覆盖和回滚方式，再决定是否单独申请退场。

本方案的默认选择是：浏览器测试按风险和耗时分组、性能优化以测量结果排序、兼容入口继续保留、数据库暂不变更。每个 Codex 工作任务只处理一个工作包。

## 3. 分阶段工作计划

### 阶段 A：稳定自动化测试（P0）

**目的：** 让开发者能区分业务断言失败和浏览器基础设施波动，并缩短重复跑测时间。

**执行：**

- 将纯单元/服务、安全门槛、短页面浏览器、长链路浏览器拆成独立命令与报告阶段。
- 先测量现有浏览器启动、页面载入和 CDP 调用耗时，再决定浏览器复用方式；如果复用可能造成用例状态串扰，则按模块隔离浏览器进程。
- 每个浏览器失败保存用例名、模块、路由、viewport、浏览器/Node 版本、控制台错误、网络违规、超时阶段和截图路径。
- 对明确的浏览器启动、CDP 连接等基础设施错误允许最多一次隔离复跑；断言失败不自动重试。首轮与复跑状态都写入机器可读结果，flaky 不伪装成首次通过。
- 分开输出 full-suite、isolated-retry、WP01 发布门槛 JSON/日志，避免混淆 676 项深测和 108 项离线回归。

**验收：** 每组可以独立运行；一次失败可定位到用例及失败阶段；重试不会覆盖首次结果；总结果准确列出 pass/fail/todo/flaky/skipped；执行现有完整回归，报告耗时基线与改进值。

### 阶段 B：建立性能基线（P1）

**目的：** 找到真实耗时热点，避免无数据的缓存、数据库或前端重构。

**首轮测量范围：** People 列表及筛选、客户经营列表、人物详情、跟进列表、招募列表、活动列表，以及知识文件导入任务状态查询。使用隔离浏览器/虚构夹具，不发生产写入和外发动作。

**记录指标：** 页面可交互时间、关键数据请求耗时、p50/p95、请求数量、重复请求、返回行数、分页边界和浏览器长任务。服务侧只记录不含个人信息的耗时与队列统计。

**数据库审查：** 仅只读访问 `public` 元数据与授权的查询计划；不运行可能执行昂贵全量计算的生产 `EXPLAIN ANALYZE`，不读写 `pr`，不加索引、不改表/视图/函数。

**验收：** 产出基线表、最慢的 3 个可复现路径、每个路径的证据与优化估值；如果没有稳定热点，明确建议不改系统代码。

### 阶段 C：逐项优化已证实热点（P1）

**准入条件：** 阶段 B 有可复现数据，能指出具体页面/函数/查询和主因。一次只改一个热点，先说明影响页面、接口、字段、权限、兼容行为和回归范围。

**默认优先顺序：** 消除重复读取或客户端重复请求；缩小不必要的字段/载荷；在不改变过滤、排序、分页和权限语义的前提下优化查询；最后才评估缓存或结构调整。不得仅为跑分快而弱化刷新、授权或最新数据语义。

**验收：** 同环境同夹具复测，p95 至少改善 20% 或达到事先记录的目标；请求数/载荷有可解释的下降；相邻页面功能回归全通过；没有新增未确认写入或权限路径。未达到目标则撤回该优化建议，不累积“顺手重构”。

**数据库变更约束：** 当前计划不授权 schema 变更。若数据证明需要索引、列、视图或函数调整，先输出 public-only migration、rollback、锁与运行时间影响、依赖视图清单和回归计划，停止在待确认状态。

### 阶段 D：完成 PMC11 到 Person AI Gateway 的覆盖闭环（P1）

**目的：** 让旧套件退役后的覆盖缺口可见、可验收，同时避免把测试迁移误报为旧云函数已经迁移。

**先做分析与测试：**

- 逐个映射旧 AI 函数入口、调用页面、身份来源、读取字段、写入目标、审计记录、权限和失败兼容行为。
- 映射到现行 Gateway skill/task、Person 身份选择、AI 历史记录、人工确认与服务端写入边界。
- 给每条路径标记：已有覆盖、缺少覆盖、确实无人调用、需要保留的兼容行为。
- 先为现行 Gateway 补测试覆盖，不复制已经过时的旧 prompt/表结构断言。

**迁移闸门：** 如果确需改变旧入口或端点行为，先提交影响说明、兼容方案、逐端点迁移表和回归范围，并等待用户明确确认后再改业务代码。不得删除/重命名旧云函数或路由；没有新执行器覆盖的命令必须继续拒绝写入。

**验收：** PMC11 TODO 只有在对应 Gateway 路径获得明确的新断言后才能移除；每个迁移端点都有调用面、权限、数据归属、人工确认与失败回退证据；跨模块 regression 通过。

### 阶段 E：清理重复入口与冗余维护成本（P2）

**执行：**

- 检查 `admin.html`、`console.html`、M07 新招募目标页和旧 URL 的静态引用、动态跳转、书签兼容与外部链接证据。
- 记录每个入口的唯一业务功能、认证边界、调用函数和退场替代路径。
- 先合并重复测试 helper/过期断言，不移除旧业务实现或函数。
- 只有在替代入口完整、真实调用者清单有证据、回滚方案可用且用户针对移除项明确确认后，才执行页面/路由退场。

**验收：** 没有断开的旧链接；Console 路由、登录、客户列表/详情、跟进、活动、招募、回收站相邻回归通过；确认删除范围精确到页面/路由，不连带删除用途未确认的函数。

## 4. 可直接交给 Codex 的顺序任务

把以下任务按顺序分别发送给 Codex。每项任务先检查当前 `master` 与报告版本；若远端已前进，先对齐并检查差异。后项依赖前项结论，遇到审批闸门时完成允许的只读分析后暂停在明确的待确认项。

### Codex 任务 1：测试运行器可靠性

```text
以 docs/work-packages/automated-deep-test-20261106.md 和 docs/work-packages/system-optimization-plan-20261106.md 为依据，优化自动化测试的分组、失败诊断和结果汇总。先检查 tests/regression/browser.cjs、tests/regression/run.cjs、package.json 及现有 browser test harness，测量现状后再改。将单元/服务、安全门槛、短浏览器、长链路浏览器分成可独立运行的阶段；记录浏览器/CDP失败阶段、viewport、控制台错误、截图和首次/复跑结果；仅明确的浏览器基础设施故障可最多隔离复跑一次，断言失败不能自动重试或伪装通过。分别生成 full、retry、WP01 的机器可读汇总。不要改业务页面、云函数、数据库、登录/RLS语义或已有旧路由。按 AGENTS.md 执行适用回归并记录耗时前后对比；只提交这个工作包需要的文件。
```

### Codex 任务 2：建立只读性能基线

```text
以优化方案阶段 B 为范围，为 People 列表、客户经营列表、人物详情、跟进、招募、活动和 OCR 任务状态建立可重复的性能基线。先核实测试使用隔离浏览器和虚构夹具；测量页面可交互时间、关键请求 p50/p95、重复请求数、载荷量和分页行为，并给出最慢的 3 条可复现路径。数据库只读检查限定 public 元数据和安全查询计划；不要执行生产写入、昂贵 EXPLAIN ANALYZE、pr 查询、schema 修改或真实客户数据读取。此任务只产出测量脚本/报告，不修业务功能。没有稳定热点时明确建议不改代码。
```

### Codex 任务 3：单热点性能修复

```text
仅依据阶段 B 已提交的性能证据，选择 p95 影响最大且修复边界最小的一条路径优化。编码前列出影响页面/API/字段/权限/旧兼容行为及回归范围；如果会改变现行业务行为，先停在影响说明并等待用户明确确认。默认只做无行为变化的重复请求消除、载荷缩小或查询改进；不得顺手重构其他模块。若需要数据库变更，先提交 public-only migration、rollback、依赖视图与锁影响分析，不执行迁移，等待单独确认。复测同一夹具，目标至少改善 p95 20% 或达到事先设定目标，并运行修改功能及相邻旧功能回归。
```

### Codex 任务 4：PMC11 迁移映射与新流程覆盖

### Codex 任务 5：Console 与 Legacy 入口调用面审计

```text
检查 admin.html、console.html、M07 新招募目标入口、旧 URL 和所有静态/动态调用者，输出入口—功能—权限—调用函数—兼容链接—替代路径矩阵。默认保持 admin.html 和所有旧 URL/云函数，不删除、不重命名、不抽离旧单文件业务实现。只清理有明确证据已过时的测试断言或重复测试 helper。需要移除页面、路由或云函数时，列出调用者证据、兼容方案、回滚方案和 regression 范围并等待用户针对具体移除项明确确认。
```

### Codex 任务 6：独立工作包收尾与发布验证


## 5. 完成定义

- 自动化结果区分断言失败、环境失败、flaky、TODO 和既定 skip，首次失败记录不会被复跑覆盖。
- 有基线数据支撑的性能优化能在同一环境复测；无证据的模块没有被顺手改写。
- PMC11 的旧入口与 Gateway 覆盖映射完整；TODO 仅由可验证的新行为测试关闭。
- Person/Customer 数据归属、People 招募筛选、M04 附件、M07 路由、M02 登录/设置和旧链接兼容都保留已验证语义。
- 每个工作包独立提交、回归和发布；发布记录列出改动面、性能前后数据和未验证项。
