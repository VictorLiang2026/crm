## 测量方法

新增 `npm run test:performance:baseline`，复用本地隔离浏览器与网络拦截，在 1024×768 的 iPad 视口加载真实 Console 模块，并用本地 API stub 返回合成数据。浏览器不连接 CloudBase/生产服务；没有读取客户数据、调用云函数或写入业务数据。

每条路径覆盖 30 条目录页数据（目录虚构总量 1,240），人物跟进时间线和附件导入队列每页 20 条，知识治理/导入状态返回 120 条虚构来源并显示 20 条。每个完成轮次对 8 条路径各采样 30 次；另执行了 3 轮每条路径 7 次的快速校准。下表展示两轮完整高采样运行的范围。交互 p50/p95 从调用页面 renderer 到目标 DOM 出现计算；分页 p50/p95 从点击下一页到本地 mock 响应渲染计算。API 时间仅表示本地 fixture 生成/序列化开销，不是服务时延。

两轮 30 次采样都显示 People、招募、活动列表首屏 p50 约 17–20 ms；列表分页 p50 约 16–17 ms。People 目录首屏的 p95 范围最高为 27.6–36.8 ms。知识治理页在 120 条合成来源时的响应约 47.6 KB，是本轮最大的合成 payload，但仍只有一次请求；没有重复请求和长任务。人物详情总览调用 5 个只读 mock action，人物时间线 3 个；stub 处理时间低于 1 ms，无法据此估算真实网络往返的影响。

按本地首屏 p50 排序的前三个候选观察路径是 People 目录、招募目录和活动目录。三者跨两轮的 p50 范围分别为 17.2–20.1 ms、17.0–18.0 ms、17.0–17.8 ms；p95 范围均低于 37 ms。它们是本地渲染开销最高的三条被测路径，但耗时很低、没有重复请求/长任务，也没有稳定的服务瓶颈证据，因此不是代码优化准入项。

## 结论与建议

当前证据只能说明固定 mock、暖模块加载和本地 DOM 渲染的成本较低。两轮高采样的 People、招募和活动结果接近，没有可复现的前端瓶颈；测得的 p95 波动与偶发 CDP/调度尖峰不能归因到具体业务代码。知识治理列表 payload 是观测到的最大值，但合成规模仅 120 条，尚不能证明生产响应过大。详情 5 次请求也没有真实网络延迟证据，不能单凭请求数量合并接口。

**本工作包不触发任何业务或数据库性能修复。** 当前最合适的动作是保留基线；若要判断线上服务热点，需之后明确授权一个不含个人信息的只读环境/读取口径，在能真实测到网络请求的浏览器中采集至少 30 次，并单独记录各服务请求的耗时、载荷与样本量。获得真实、可重复的 p95 热点后，再按优化计划任务 3 一次只修一个路径。不得用生产真实客户数据作测试夹具。
