# 旧版兼容工作区：第二轮精简与新版升级方案

日期：2026-10-25。核对基线：ca5ef5eb3a7313c761cf68764ac7d69c3c36245d / release-20261025-151000。
本方案基于当前源码、M00–M19验收记录与本轮三端基线核对。它是个人保险营销工作台的产品方案，不是团队CRM扩建方案。

**L00 已完成11张重复卡片清理。2026-10-25 用户进一步授权按本方案自动逐包完成 L01–L08，常规选择采用推荐方案；每包验收、发布、三端核验后进入下一包。** 保留全部旧 URL、后台服务和数据。L00 发布结果见[实施记录](../../specs/legacy-workspace-exit/evidence/L00.md)，后续状态见[逐包指令](../../specs/legacy-workspace-exit/tasks.md)。

## 1. 产品结论

目标应是“日常业务在新版完成，不必理解新旧两套系统”，而不是把旧版菜单搬到另一个抽屉。
先将旧版区从17卡片减到6卡片（减少约65%）；随后逐个补齐有价值的差异，达到条件就移除对应残留入口。最终More仍为知识与话术、经营分析、设置、回收站四主入口，不新增第二套客户、文件、AI历史或统计中心。

需要区分三件事：
- 移除More卡片：减少重复导航，本轮执行11项。
- 新版原生替代：新版完成操作，不再跳admin.html，按L01–L07补齐。
- 删除旧路由/后端/数据：本轮及后续功能包均不包含，须对具体对象单独审批。

新版设置保留测试页链接、回收站保留旧批量恢复链接，这只是功能归位，不能声称相应功能已全部原生化。接下来是否搬测试工具，按个人日常价值判断，不为“迁完”复制开发维护页。

## 3. 六项升级方向

### 3.1 人物里的客户经营视图：优先做，价值高

保留人物统一目录，客户经营视图内补“跟进状态”和“招募状态摘要”。跟进状态建议使用已有逾期/今天/30天内/久未联系口径；默认只显示重要状态，展开可看计算依据。状态排序/筛选必须在服务端完成，不能只处理当前页。

用户路径：人物→客户经营→看待跟进原因→同一Person时间线→记录互动→查看下一步。与Today共用事实和链接，不生成第二套待办。已有三类优先级、客户阶段与角色转换不重做。

保留基础信息由Person维护、销售/招募字段属于各自角色。存在未关联身份时明确提示；不得静默创建角色或让AI选人。旧客户入口需待AI解析新增差异也有对应路径后再退出；只补状态不代表全链迁完。

### 3.2 经营分析：补“为什么卡住”，不做团队BI

保留三类事实摘要，新增默认折叠的阶段详情：人数、逾期、停留中位天数、滞留、近30日进入/推进；有空值就显示未知。先复用funnel_insight.stats已有字段，不另造统计表。

小样本不生成貌似可靠的比例。旧页面写“转化率”不代表其SQL就是同一批人的历史转化：必须核对分母、时间窗、终态和去重规则；静态阶段分布只能按事实口径命名。当前customer-linked机会覆盖不能包装成全部Person机会。

AI仅解释可见事实，点击后生成；失败保留事实，不自动改阶段或批量建行动。缺少精确服务端钻取时，按钮只能叫“打开工作区”，不能冒充“查看这N人”。

### 3.3 AI历史：从“建议档案”连接到“下一步”

只增强现有AI历史。Legacy来源增加日期依据：生成日期/建议跟进日期；提供今天、逾期、未来7天等筛选快捷项，按服务器日期范围查询。列表突出人物、建议时间、话术摘要、跟进目标，原文仍可展开；空日期不能归为逾期。

旧建议保持历史只读。若后续需要“转成行动草稿”，必须复用现有行动Plan/Preview/Confirm/Execute，重新核实Person、日期和范围；无执行器拒绝执行。一次采纳不等于已经联系，联系不等于业务成效，Outcome单独记录，不把Legacy ID当Runtime结果ID。

先补筛选与阅读即可退出旧建议库主入口；行动草稿是下一步价值增强，不能成为复制旧建议表或批量自动执行的理由。

### 3.4 人物资料与OCR：值得迁，分两步

新版已有原件保存、解析草稿、重试、人工核对、应用和撤销，不能再建设“资料中心”。
第一步补常见可提取文字的PDF：保存原件→提取文字→AI草稿→人工核对。限制文件大小、页数、文字量和超时；扫描PDF/加密PDF失败显示原因并保留原件，不能返回空成功。复用当前4MiB/文件、10文件/队列边界，需改变时另行说明。DOCX解析为低优先级可选，原件仍可保存。

第二步补“尚无人档案时导入”：后台提出姓名候选，服务端调用PersonService.resolveName()，人确认已有身份或批准创建，再进入资料审核。沿用现有预览/确认及幂等，不把AI抽出的全部短句变成事实或任务；不能用旧解析直接覆盖基础资料。

仅在旧照片/OCR实际常用输入类型、历史读取、撤销及解析新增均有安全路径后退出旧入口。旧浏览器OCR/PDF引擎不是必须原样复制的实现；按可靠性和维护成本选择复用，但必须保留用户结果和失败说明。

### 3.5 活动资源：把嘉宾变成可经营的资源

仍使用活动→活动资源，不另建“嘉宾CRM”。补嘉宾关系阶段、联系到期筛选；卡片显示最近/下次联系、合作次数和当前状态。资料里的姓名/联系方式继续指向Person；阶段、专业和合作信息留在嘉宾角色。

一次交流后可以提出下一步，但以现有Action作为唯一行动来源，避免next_contact_date和Action各自生成重复提醒。先显示现有字段和精确筛选，再另行评估统一行动关联；不能为本次目录收尾暗改全部日期语义。

活动准备中的嘉宾/主题推荐应读当前活动目标、受众、资源及历史结果，给候选和理由；人确认后使用既有参与者/主题接口。未接入服务端预览执行器的自然语言写入必须拒绝。此能力属于活动准备，不阻塞已覆盖的主题目录退出。

### 3.6 招募目标：个人目标测算，去掉团队色彩

保留月目标、实际、差距；增加折叠“目标测算”：输入签约目标和明确的转化假设，展示新增人才需求及假设说明；参考上月时标注草稿，只在确认保存后生效。测算用确定性公式，不需要AI编数字。

基准编辑可放高级区，来源不明的数值标为“个人假设/历史参考”，不得作为已核验国际行业标准。旧页面硬编码的公司团队增长、MDRT人数等宏观卡片不建议搬到个人操作页；不核实其有效性，也不将其当当前事实。小样本隐藏或明确限制转化结论。

AI的作用是解释目标差距、给本周可行的联系建议；先只读展示。自然语言修改目标仍须完整确认链。无需团队排行榜、组织编制、佣金和绩效考核模块。

## 4. 已移出More但仍值得考虑的批量恢复

优先级低于日常跟进与AI筛选。用户偶尔误删多条时，在现有统一回收站增加多选，逐条展示恢复主体、关联记录和原删除批次，确认后执行。两类候选人分路，过期预览/权限错误拒绝，部分成功明确显示，仅重试失败项。不新增永久删除，不把“全选当前页”扩成全库。

这项通过后，可退出回收站内的两个旧批量链接；是否保留受控测试工具与业务迁移完成无关。维护工具可以长期在设置高级区，不要求变成普通业务模块。

## 5. 不建议迁移或新建

- 不新建跟进、产品资料、礼品、主题、两套报表或第二个AI历史中心。
- 不为兼容旧布局复制全部列、图表、标签或原先按钮的位置；保留有用操作及结果。
- 不迁入未经来源核验的团队排名、行业参考宣传卡片；个人目标以可说明的假设为基础。
- 不新增跨客户批量改阶段/批量发消息；当前没有已核实的需求和完整安全执行器。
- 不把历史AI建议全部复制为新行动，不把星座或未经验证的异议推测当人物事实。
- 不将客户已有products当公司产品知识库。本轮没有纳入公司政策导入、星座、外发消息、团队管理。
- 不把“去掉旧版字样”当迁移完成；凡仍跳admin.html，文档必须如实标记兼容。

## 7. 退出标准

每项都要有“旧操作→新版路径→原记录/原ID→实际测试→未覆盖点”的验收行：
1. 核心读/写/查询/失败重试和必要高级能力已覆盖，或者用户明确决定不再保留某具体能力。
2. 人物身份、来源、数据口径、软删除/批次、权限与旧请求契约保持；不能靠复制数据制造覆盖。
3. 新路径在iPad中英双语可发现、可完成操作，不依赖手工输入URL；历史旧URL继续可打开。
4. 已有相邻功能regression通过；真实用户登录业务未验证时明列，不凭哈希声称业务等价。
5. 每包有针对性回退、发布标签和三端核验。改库才需要成对migration/rollback；没有改库不得为了形式制造迁移。
6. 最终More不再展示旧版兼容区，日常人物/机会/活动/招募/AI链不再跳旧页。设置高级维护及历史来源标签可保留，并在清单中区分。
