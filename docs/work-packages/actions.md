# Public Actions and ActionService (2026-09-28)

Baseline: clean local and GitHub `master` at `f847af635bb9d0ba0dd1339d963e53ff95f6f619`, tag `release-20260928-093326`. The online `admin.html` and 27 CRM Functions (116 source/config files) matched the local files. Production CloudBase PG context was `crm-d1gkae8ddc930d151`, `public`; `public.actions` did not exist. Live reference schemas showed bigint IDs on `persons`, `opportunities`, `interactions` and `activities`. Existing Person, Interaction and Context Item ledgers used forced, service-role-only RLS.

Scope: added `public.actions` with the requested 20 fields plus `created_by_uid`, `completed_by_uid`, `confirmed_by_uid` and `confirmed_at` for human and AI confirmation audit. Person is required; opportunity, interaction and activity are optional restrictive foreign keys. A trigger rejects an interaction for another Person and an opportunity whose `customer_id` differs from that Person's `legacy_customer_id`. It also prevents changes to identity, links and provenance after creation and refreshes `updated_at`. Priority is `low`, `medium`, `high` or `urgent`; status is `open`, `in_progress`, `completed` or `cancelled`. Each optional score is 0–100. `priority_score` is stored without an implicit formula. Completion requires both time and actor; `ai`/`ai_*` source rows require confirmation actor and time. No legacy action field, action-center view, Function, page, route or feature flag was changed.

`ActionService` is a new shared source module only. It provides a bounded `listForPerson`, a manual `createManual` that fixes `source='manual'` and checks active references, and a Person-scoped `complete` that records the actor. It requires an authorized server-side database callback; no existing Function imports it yet. Accordingly, the production HTTP/API path for this service is intentionally not exposed or live-tested in this work package. AI action candidates remain preview-only and cannot be persisted through this service.
