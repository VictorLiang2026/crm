# WP5 活动与参与者

发布基线为 `release-20261111-130254`（`5e64617`）。变更涉及 Console 活动页、人物详情的嘉宾与活动分区、活动复盘预览、`person_360` 和 `public` 数据库。

- 活动 → 签到 → 更改状态提供报名状态及到场状态。可分别记录报名、取消报名和实际出席。既有邀约、签到、缺席及统计仍使用原参与记录的 `status`。报名事实按参与记录 ID 关联，保存时核对活动、参与记录、版本；同时编辑两种状态在一个事务内提交。
- 人物详情直接分页查询绑定该 Person 的有效活动，每场一行，列出报名及到场情况，并提供已明确关联的跟进行动入口。嘉宾关系、活动时间线和原有分页继续可用。
- 复盘执行前展示服务端绑定的 Person ID、现行姓名、来源和拟写入内容。操作人核对身份与意向后确认执行。活动签到本身不写客户、招募、人物角色或互动。
- 数据库迁移 `20261111134000_event_participation` 增加受限回应表和服务端函数。未给浏览器角色分配新权限，未修改旧视图、报表或批量回填历史。独立开发中的公开报名系统保留原工作区。
- 恢复代码可按发布基线部署受影响的前端模块及 `person_360`。SQL rollback 仅在回应表为空时允许移除新增对象；出现真实报名回应后需先评估保留与恢复。

## 验证

- 独立 PostgreSQL 演练迁移、回滚、重新应用，验证多重角色、互不相混的出席与报名、取消、软删除与恢复、更新冲突、跨活动范围、已关联行动、分页及防止丢失回应的回滚保护。
- 人物目录数据库回归通过。16 项专项回归涵盖活动管理、参与者、嘉宾、主题、复盘、人物活动视图、三端中英文布局和人工确认。
- 云端只读抽检 15 位人物，活动场数与实际出席数均与底表聚合一致。上线前的 3 条有效参与记录均无已确认 Person ID，已保留；本次没有代为匹配。
- 写入测试在隔离数据中完成。本轮没有使用实体 iPad、iPhone 登录并操作真实活动。
- 全量隔离回归 104 项通过、5 项预设跳过、0 项失败。WP01 权限、匿名网关及身份基线通过。已更新 6 个 Console 模块和 `person_360`，生产函数拒绝未经验证设备的调用。发布标签为 `release-20261111-171231`。
