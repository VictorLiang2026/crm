# 参与名单发布验收记录

## 使用路径

员工在 Console 进入「参与名单」，先选活动，再导入 CSV 或 XLSX。核对每行姓名，遇到同名时可选具体人物、复用参与者、单独建参与者或跳过。确认后本场名单即为实际参加记录。同一参与者可以参加多场活动，同一活动重复导入同一参与者只记一次。

参与者资料包括姓名、毕业学校、微信、电话、公司、行业、毕业年份和其他信息。独立参与者的详情可编辑资料并查看历次活动。人工关联 Person 后，人物详情也可查到全部活动。关联人物的姓名、微信、电话和公司从人物档案读取，名单导入不会覆盖这些字段。

## 变更与回退

- 起点为 `release-20261112-001938`，提交 `4b02c169`。在隔离的 master 发布目录中实施。
- 三对数据库 migration 和 rollback 分别对应名单业务、权限收敛及停用报名。原参与关系表是经营报表、活动与人物角色的共同依赖，保留其表和主键。以名单关联识别实际参加记录。活动没有导入记录时显示尚未导入。
- 清理前核实旧公开报名提交及活动回执均为零，旧参与关系 19 条，其中 3 条有效。清理事务锁定相关表，重新核对报名提交与参与人，再删除没有名单关联的旧参与关系。没有迁移旧签到或报名数据。清理 rollback 可恢复结构与函数，无法还原已清理的业务记录。
- 原有五把环境 API Key 沿用。旧公开路由、托管资源、两个专属报名云函数和数据库签名通道退役。员工端从既有人物服务进入，沿用设备及员工权限。
- 第一次清理尝试因报表函数定义缺少语句终止符回滚。第二次因旧人物角色触发器无法处理空 Person ID 集合回滚。最终版保留具体人物的角色重算，对独立参与者直接结束该次角色同步。隔离 PostgreSQL 测试同时验证独立、关联、解关联以及回滚。

## 发布核验

- 正式标签 `release-20261112-091506`。本工作包和相邻模块专项回归 59 项全部通过。系统回归 104 项通过，5 项跳过，WP01 发布门禁无阻断项。
- 清理后线上 public 权限目录剩余 251 个对象。确认退役的 53 个对象已移除，其中 36 个为报名签名所用扩展函数。参与关系表仅收回原有匿名写权限；其余目录差异逐项核对。
- 生产 Console 和参与名单脚本返回 HTTP 200，旧报名页及其公开脚本均返回 HTTP 404，公开报名网关路由数量为零。

## 验收证据与边界

- 业务自动化覆盖桌面 1440×900、iPad 820×1180、iPhone 390×844 下的选活动、文件映射、身份核对、预览、确认、未关联者历史和横向溢出检查。浏览器回归使用 Edge 和虚构数据。
- PostgreSQL 隔离回归覆盖同名人工选择、导入不覆写 Person 联系方式、跨场复用、单场去重、重复确认、并发版本冲突、移出一场及关联前后的活动历史。迁移回归覆盖清理前有新报名时整笔拒绝及结构往返。
- 相邻模块回归包含人物名单导入、活动工作台、嘉宾、活动复盘和设备委托。生产环境进行来源、权限目录、设备拒绝和发布核验。已批准设备上的 Safari 实机登录及生产名单写入须与模拟视口验收区分。
