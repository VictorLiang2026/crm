# 首页晨间简报与经营驾驶舱的参与名单读取修复

基线为 `release-20261112-091506`（`fdc6ab7`）。首页两项请求分别是 `today_coach.daily_review` 的 morning 视图和 `today_coach.cockpit`，两者均通过 `loadAll` 读取活动参与事实。

## 根因和改动

- 生产云函数日志出现 `ROSTER_READ_FAILED`。在生产以原有服务角色执行首页的只读 RPC，只返回行数即可复现 PostgreSQL `42703: record "c" has no field "Id"`。
- 已部署的函数将客户关联查询命名为 `c`，与 PL/pgSQL 的导入命令记录同名。数据库解析客户编号时误引用了记录，即使名单为空也失败。
- migration `20261112093500_roster_facts_customer_alias` 将客户查询显式命名为 `customer_row`。仅在原函数体摘要匹配时更新，并核对修改后的摘要；SQL rollback 可逆。沿用原 RPC 签名、执行权限和结果结构，无业务数据写入。

正式标签 `release-20261112-094049`。在生产核对了迁移历史、目标函数体及调用权限。相同服务角色和相同首页查询参数在修复后返回 0 条，影响行数为 0。系统回归 104 项通过、5 项跳过，WP01 门禁通过。页面和云函数均沿用基线产物。

生产 `today_coach` 的自然请求在北京时间 09:40:30 返回经营驾驶舱的 trends 和 reminders，09:41:13 返回晨间简报的 sections 和 morningBrief，两次返回均无 error 字段。仅核对返回结构，未保存或输出业务正文。

## 验证

- 新数据库用例在修复前复现 42703，验证空名单、独立参与者、客户／候选人／嘉宾身份、日期和活动过滤、分页游标、软删除、匿名拒绝，以及回滚后重新应用。
- 两项首页请求使用现有设备校验路径进行隔离回归，验证空名单照常返回简报与驾驶舱；另覆盖三种视口的名单操作和已有 Today 功能。专项共 24 项通过。
- 生产探测限于聚合计数和权限元数据。未操作真实客户，也未用用户的已登录手机或 iPad 进行实机验收。
