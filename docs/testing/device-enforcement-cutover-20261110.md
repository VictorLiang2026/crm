# CRM 设备校验：切换与验收

**状态：独立开发分支，不能作为生产已强制的证据。** 生产的首台申请与签名探针见 [后台说明](crm-members-device-enrollment-20261110.md)。设备绑定的是账号与浏览器密钥，不是 iPad 硬件序列号；换 Safari 用户配置或清理站点数据需要重新申请。开发基线为 3ed2875，首台申请修正版本为 release-20261110-080100。还没有批准设备时，不部署强制版本。

## 切换条件

1. 成员在自己的 Safari 普通窗口申请。管理员对照身份认证 UID 与完整设备码，在 CloudBase 后台批准唯一申请。回原浏览器再次点击申请，收到“设备签名验证通过”。不要让管理员代替成员申请，不采集密码或设备私钥。
2. 只读核对发布 HEAD、服务清单、受影响函数、两个桶的策略、真实报名功能是否已发布。开发基线包含 29 个私有函数及单独的 knowledge_mcp；当时生产查询 activity_registration 返回未部署。若部署清单变化，应重新区分公开报名、仅本人报名管理和 CRM 管理操作，不可把整只报名函数列入公开例外。
3. 记录前一可用模板及配置，不输出密钥。assistant 的 CRM_KNOWLEDGE_MCP_OWNER_UID 必须是核对过的原 GPT 授权人；只控制新授权，不更换旧 OAuth 密钥、令牌或范围。pmc18_observer 的 CRM_OBSERVER_TRIGGER_SECRET 及现有 pmc18_daily_0200 触发器消息必须配对，保留调度时间，验证触发来源；不得凭事件自报 Timer 放行。已有 OCR 触发密钥与时间不变。
4. 审查并分别实施 20261110153000（内部单次凭据）、20261110153100（私有上传分片）。除单独授权的两个文件桶，所有对象都在 public。按真实目录核对新增对象的最小授权、录入精确安全基线，刷新 WP01/WP04 证据，通过发布门槛。若运行时角色与预期不符，修复服务端通道，不给浏览器角色加表权限。
5. 在原系统上先验证 GPT 知识读取、授权的跟进上下文读取、OCR 和观察任务基线。安排短暂 CRM 切换窗口；先验证 GPT/内部服务跨版本调用，再将对应目标和调用方切为签名协议。公开 OAuth MCP 本身不接浏览器设备校验、不部署未改动的 knowledge_mcp。只部署实际更改的 CRM 函数和明确列出的静态文件。服务端检查先于数据查询；不依赖页面跳转。任何业务函数仍接受普通账号直调时，不宣布完成。
6. 先用**合成**招募候选人与临时知识来源，在已批准浏览器走文件代理验证上传、完成、打开、替换及清理，特别验证实际 PG 文件服务支持分段下载与最长文件大小。绝不拿已有客户附件做测试。验证通过才单独实施 20261110153200，只改变五条专有策略的适用角色。发现共享策略、遗留其他入口、服务端上传/下载失败或其他桶依赖，停止该项。该迁移的回滚会恢复旧账号直连风险，不能自动执行。
7. 对切换前签发的招募链接做合成验证：旧实现请求 3600 秒，可继续有效至过期。记录最后可签发时间及实测过期时间。在旧链接仍可打开或无法核实有效期时，明确列作例外。新代理不签发存储链接；本地 blob 是本次下载的副本，不能远程回收。撤销保证的是后续请求被拒绝，不是抹除已经显示或下载的内容。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 无会话、匿名会话、其他普通账号，直接调用新旧业务接口及文件接口 | 任何业务读取或修改前被拒绝；普通账号不能批准自己 |
| 正确的成员密码＋未申请或待审的新浏览器 | 只能走申请流程；两个工作区不展示资料 |
| 已批准设备 | 两个工作区可访问人物、客户、跟进、招募、活动、回收站；知识文件要匹配登录人及来源，招募文件匹配候选人及已绑定字段 |
| 同一个签名重放、改业务参数、冒用其他函数、伪造 UID 或定时任务 | 拒绝；两个人共用同一 iPad 也须分别批准 |
| 后台撤销或停用，浏览器不退出 | 已签发但未消费的挑战失败；下一次业务读取和文件分片均拒绝；Safari 恢复页面先验证再显示 |
| 收紧文件桶后，持原普通账号直接调用存储 API | 两桶直读、上传、改写、删除均不能绕过；其他桶不变 |
| GPT 旧授权、未授权连接、非授权成员发起 OAuth | 旧授权可用；未授权访问失败；普通 CRM 成员不能为自己的 GPT 发放新授权 |
| 活动报名 | 若已部署，两个合成报名者交叉换编号/令牌不得互读；公开报名和报名者本人操作不要求 CRM 设备；管理操作须验证设备。未部署要明确标记 |
| 定时任务 | 只允许已验证的定时触发器执行其固定操作；使用普通账号伪造事件失败 |

## 代码与隔离验证

- 两个工作区与 OAuth 同意页共用签名客户端；旧管理页保留原有登录、超时及业务调用入口。每次读取校验，不缓存“已批准”结果。person_360 用服务端凭据验证签名与一次性挑战；其他私有函数还将验证结果与其 CloudBase 实际调用者比较。
- 内部转调按来源、目标、动作及参数签发短期一次性凭据。MCP 仍验证已有 HMAC，定时任务验证其独立密钥；普通客户端不得自报“内部调用”。新授权与已有授权分开。
- tests/device-access/enforcement.cjs、device-registry.cjs、device-browser.cjs 与 storage-policies.cjs：仅使用合成身份/数据、隔离 PostgreSQL 及浏览器；覆盖签名、撤销、套用他人身份、分片及回滚。需要本机 PGlite 时可设置 CRM_PGLITE_MODULE。测试夹具不注入生产入口。
- 保留生产验收记录：首台成功签名、同密码未批准浏览器、获批设备的业务及附件、撤销、旧 URL 过期、授权 GPT、报名（如已上线）和定时任务。源码一致与隔离测试通过不能替代这些记录。
