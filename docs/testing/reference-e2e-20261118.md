## 扫描实测发现与修复

合成 DOCX 包含两页纯图片、四个独立场景和两条页尾校验码，没有可直接提取的正文。图片文件名/ZIP 顺序刻意与正文引用顺序相反。

1. 原解析器按 ZIP 媒体顺序读取，实测先得到第二页 `SCAN-B29`。改为读取正文的图片关系与出现位置，保留正文、图片之间的顺序；未引用、缺失/外链、暂不支持的媒体分别提示。
2. 原 OCR 将同一页多个段落合并成一个范围，导致同页多个场景不能独立抽取。现在保留 OCR 换行和来源段号，继续使用模型返回的原文范围，避免模型改写原文。
3. OCR 异常原先只记警告后跳过。现在任务明确失败，重试保留前页检查点并重做失败页；空 OCR 同样失败。旧解析器检查点首次重跑时从保存原件重新建立正确页序，并明确提示；不修改已导入话术。
4. 两条真实扫描解析任务均在 60 秒模型等待边界超时（审计任务 #323、#332）。仅将 reference 队列的 Gateway 等待预算提升到 120 秒、单次尝试，低于现有 assistant 180 秒函数限制；模型仍由 Gateway/CloudBase 配置选择。
5. 失败任务的 `error` 字段被通用页面数据适配器当成接口错误，重试按钮无法出现。改为独立 `failureCode`，保留 `failed` 和进度，使页面能显示重试。
6. 完成但没有可导入场景时，仍展示覆盖详情、遗漏和媒体警告；重试真正重新解析已保存原件，不再重复展示同一份空结果。
7. 修复页序后真实模型完成 18/18 段，但把四组“客户异议 / 参考回应”拆成八条。强化完整场景约束，并根据原文明确的 S/O/场景标题合并同场景问答范围；保留标题和完整回应，不把页尾或下一场景混入。增加捕获该真实输出形态的回归测试。
