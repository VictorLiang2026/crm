# release-20260923-002320

## 变更

- 为 customers、followups、gifts、photos、policy_review_reports、ocr_records、products、recruit_candidates、recruit_followups 增加删除批次字段。
- 新增 `public.crm_delete_batch`，将客户/候选人的级联删除与恢复合并到单一事务，并按 UUID 批次精确恢复。
- 历史无批次记录只恢复客户或候选人本身，不推测或恢复历史关联记录。
- 客户与增员回收站显示本次可恢复计数和历史记录提示，保留原入口、分页、批量恢复与 API 主要字段。
- 新增离线回归与生产隔离测试脚本，以及数据保留型 rollback。

## 发布范围

- 数据库迁移：`20260922080000_delete_batches`，远端任务 `task-764ef4da` 成功。
- 云函数：`customers`、`recruit_candidates`。
- 静态托管：`/crm/admin.html`。
- 未部署或修改其他 CRM 函数；未访问或操作 `pr` schema / `pr_*` 函数。

## 验证

- 完整离线回归：57 PASS / 0 FAIL / 5 SKIP。
- 生产隔离写测试：客户批次、候选人批次、历史记录、单独硬删除子记录均通过；测试记录清理后 4 类对象剩余均为 0。
- 线上函数实际调用：两个函数的 remove/restore 与 trashList 均成功，无匹配 ID/关键词未改动或返回真实业务数据。
- 数据库：9 个 UUID 列存在；函数为 SECURITY INVOKER；EXECUTE 为 anon/service_role 允许、authenticated 拒绝；RLS 保持开启。
- 云端一致性：线上 admin.html HTTP 200 且哈希一致；26 个函数、108 个源码/配置文件与本地一致。

## 回滚

执行 `cloudbase/rollbacks/20260922080000_delete_batches.sql` 可暂停新删除，同时保留批次列和安全恢复。不要直接删除批次列，否则已删除记录会失去精确归属证据。
