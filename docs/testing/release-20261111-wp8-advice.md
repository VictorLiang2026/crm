# WP8 客户保障、招募与活动建议

回滚基线为 `release-20261111-193913`，提交 `b5258c9`。Console 桌面、iPad 和 iPhone 共用同一套业务入口与中英文字典。

## 三个场景

- 客户保障保留两列建议和两列微信话术。系统与 GPT 均沿用当前有效的知识内容版本，过滤仅用于招募的资料。来源显示编号、日期和核验状态。GPT 确认导入前重新核对引用的审核状态、所选内容与版本指纹。保单摘要通过 WP6 的当前有效报告视图读取。
- 招募与活动按类别选择审核有效的知识。来源核验失败、已暂停、失效、测试资料均不会充当参考知识。界面区分未找到与未能核验。招募评分只认候选人及其跟进记录。历史分数按生成时的候选人快照核对。招募历史列出与该结果 ID 关联的实际结果。活动模型独立返回待核实问题，旧复盘缺少该字段时仍可打开。活动的出席、重要互动与已确认身份规则继续约束候选行动和机会。
- 建议依据区分记录事实、AI 推断、待核实和下一步。历史版本无结构化依据的栏位显示未记录。知识审核时间表述为生成时核验。

## 反馈及业务作用

- 客户建议分别绑定系统或 GPT 内容指纹。修改后须重新预览。可针对曾采纳的版本补记实际结果与依据。
- 活动整份复盘反馈关联具体 AI result，复用 AI 经验的决定与实际结果流程。原始系统建议有唯一 AI result 时也同步其决定。招募保留候选人范围内的决定、后续行动和实际结果。知识本身不能证明个人意愿。
- 服务端向当前操作者签发预览，确认时重新校验目标及版本。相同预览可安全重试。仅记录对建议的反馈不会改变销售或招募阶段。活动产生的业务行动和机会仍走原有确认入口。
- 迁移 `20261111203000_advice_feedback` 新增一张仅服务角色可访问的反馈表及一个调用者权限函数。无业务数据回填。回滚脚本遇到已确认反馈会停止，以免丢失记录。

## 验证范围

- 73 项自动化测试通过，覆盖三场景相邻业务、知识内容选择、来源失效、生成历史、AI 经验和两列微信话术。Edge 模拟桌面、iPad 和 iPhone 验证中英文展示、布局边界、预览与确认。
- 隔离 PostgreSQL 演练迁移、回滚和再次应用。验证服务角色、匿名拒绝、软删除、失效预览、跨操作者拒绝、重复确认、历史版本结果、已有反馈时回滚保护。
- 生产迁移记录及新增对象均已核实。正式环境使用 service_role 对一个有效客户建议做只读反馈查询，仅返回通过与否，不保留个人正文。未对真实客户生成建议、登记决定、写入结果或发送消息。浏览器尺寸模拟未代替真机登录测试。

跨包回归另行运行了 23 项 Console 浏览器测试和 7 组隔离 PostgreSQL 演练，涵盖同人多角色、名单组合筛选、参与关系、阶段流转、行动与承诺、保单审核和经营报表。项目发布门槛的公共回归为 104 通过、5 项预设跳过。
