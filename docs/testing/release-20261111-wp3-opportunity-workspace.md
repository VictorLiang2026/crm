# WP3 机会工作区

发布基线为 9a69f48，标签 release-20261111-081929。四个视图共用一个分页查询，展示客户保障、团队招募、今日待推进及全部记录。业务 ID 在各自流程内标识记录，Person ID 用于关联人物。显式转介绍记录作为来源查看。无法可靠映射的阶段保留原值并标记待核实。

## 阶段和里程碑

- 两条流程各有五个经营阶段和三个结束结果。阶段变更需要服务端读取有效人物、业务记录和当前阶段，再返回有到期时间、绑定操作者的预览。操作人核对前后阶段、结果原因和来源后，系统只凭预览 ID 执行事务。确认时再次核实版本和上次决策，重复确认返回第一次的结果。
- 客户保障结束时写入原机会的兼容终态，并在结果表登记一次结果。团队招募的经营判断保存在 public.crm_pipeline_decisions。月度业绩仍取实际招募里程碑，记录“职业沟通”“已加入”或“继续培养”均不自动计入面谈、签约或流失。
- 今日待推进按上海日期计入到期和逾期的开放流程。保障机会优先使用明确关联且有到期日的未完成行动，招募使用候选人的下一步日期。各视图均过滤软删除，回复有效后重新出现。

## 数据与验收

两份迁移分别创建服务端经营决策记录和受控 RPC，扩展目录 RPC 的四个查询范围。保留原目录签名及其既有查询范围。迁移服务即时列表未及时显示新版本，分别核对 migrationDetail 和线上函数体确认已生效。

生产 service_role 只读查询返回保障 1、招募 573、待推进 4、全部 574，采样的招募阶段与原记录一致。生产决策表在验证时为 0 条，原有 583 条里程碑、14 条目标和 7 条基准保持原数。

内存 PostgreSQL 演练覆盖迁移与逆序回滚、历史保护、两个流程的全部阶段和结果、同人多角色、业务 ID 重号、分页、软删恢复、未完成行动、过期预览、跨账号拒绝、测试身份限制、并发版本冲突、重复确认及业绩隔离。专项测试覆盖人物详情、机会预览、招募资料与目标、AI 命令、回收站路由、中英文和三端模拟视口。本轮未在生产创建、关闭或恢复真实业务，真机视觉及人工账号登录未重新验收。
